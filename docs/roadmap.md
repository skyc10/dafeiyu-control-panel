## 已修复：桥接配置文件重启后丢失（2026-10-26）

**症状**：控制台改过白名单，容器重启后回到旧值。

**根因**：`entrypoint.sh` 用单文件软链把 `/data/bridge-config.json` 接到 `/opt/qq-bridge/config.json`。
桥接保存配置走 `atomicWriteText/atomicWriteJson`（`bridge.js:181/195`）：写临时文件后 `renameSync` 覆盖目标。
**rename 替换的是软链本身**，把它变成普通文件 —— 此后写入都落进镜像可写层，`/data` 的持久副本不再更新，
下次启动 `rm -f` 又把这批改动删掉。与 `roles/` 当初的坑同类。

**证据**：容器内用真实 Node 复现——单文件软链 rename 后类型变为 `regular file`，持久副本内容不变；
整目录软链才正常。修复前实测「运行时 3 个群 / 持久副本 1 个群」。

**修复**：不再用软链。启动时把持久副本铺成**真实文件**到工作位置，另加后台守护每 3 秒比对，
内容变化且是合法 JSON 就同步回 `/data`。顺带接管旧部署里 `/opt` 下较新的残留内容，避免丢失已改的白名单。

**验证**：模拟桥接 rename 写入 → 2 秒内同步到持久副本 → 重启后改动仍在 → 白名单与令牌完整。
